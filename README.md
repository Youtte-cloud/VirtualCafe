# Virtual Cafe 智能前台

本项目提供咖啡厅接待、直接点单、LLM 饮品推荐、
饮品与原料展示，以及购买后的制作动画。

本文描述目标交互与模块接入约定。
“当前实现状态”之外的内容均为后续开发目标。

## 1. 当前实现状态

已实现：
- 奶油风咖啡厅基础场景。
- 运行时自动显示欢迎选项。
- 点单与推荐占位面板的切换。
- 返回欢迎选项及“稍后再来”关闭面板。
- 当前四款饮品的杯体高亮、切换与清除。
- 四个临时按钮用于测试对应饮品的高亮。
- 菜单、配方、计价与库存服务已引入项目。

待实现：
- 玩家移动与接待区域检测。
- 店员模型及接待表现。
- 防止重复招呼的控制。
- 镜头过渡与饮品弹出展示。
- 正式菜单 UI 与原料选择。
- 原料展示随配置变化。
- 库存状态、Sold out 与购买确认的 UI 接入。
- LLM 文字对话与推荐配置应用。
- 制作动画与购买完成反馈。

当前使用固定镜头，自动显示欢迎面板，
作为玩家接近柜台触发接待的临时替代。

## 2. 完整交互流程

### 2.1 进入接待区域

用户进入柜台接待区域后，店员主动招呼：

“欢迎光临，今天想喝点什么？”

显示三个小选项：
- 我想直接点单
- 帮我选一杯
- 稍后再来

此时不立即展开完整菜单。

选择直接点单后进入菜单流程；
选择推荐后进入文字对话流程；
选择稍后再来则结束本次接待。

### 2.2 直接点单

用户选择“我想直接点单”后：
1. 隐藏欢迎选项。
2. 镜头稍微靠近柜台菜单牌与饮品展示区域。
3. 打开点单面板。
4. 显示饮品名称、价格和实时可售状态。

用户点击饮品名称后：
- 对应饮品模型弹出，进入展示状态。
- 对应柜台展示杯高亮。
- 在饮品侧边或上方显示原料与杯型选项。
- 显示当前配置的价格、用量和可售状态。

“弹出”指饮品模型的出现、轻微上移或放大动画，
不另外叠加一个饮品弹窗。

展示区域同一时间只保留一款当前饮品。

### 2.3 调整原料与杯型

用户修改允许调整的选项时：
- 展示的原料名称、图标或模型同步变化。
- 原料用量同步更新。
- 价格与可售状态同步刷新。
- 下单内容更新为当前配置。

例如：
- 拿铁由全脂奶改为燕麦奶，奶的展示同步替换。
- 拿铁由蓝山豆改为瑰夏豆，豆种展示同步替换。
- 400ml 改为 500ml，按对应配方更新用量与价格。

展示配方与价格以菜单服务的查询结果为准，
不在 UI 或动画脚本中另写一套计算规则。

### 2.4 切换饮品

用户选择另一款饮品时：
1. 当前饮品退出展示状态。
2. 隐藏当前饮品的原料展示。
3. 清除原来的高亮。
4. 下一款饮品弹出并进入展示状态。
5. 显示新饮品的原料、配置、价格及可售状态。

退出展示的饮品应隐藏或恢复原位与原始大小，
具体取决于使用独立展示模型还是柜台原有模型。

切换饮品不删除基础场景模型，也不扣减库存。

### 2.5 推荐点单

用户选择“帮我选一杯”后：
1. 隐藏欢迎选项。
2. 打开推荐对话面板。
3. 用户输入口味偏好。
4. 获取最新菜单与库存快照。
5. LLM 根据偏好及快照推荐饮品，显示店员回复。

偏好可以包括：
- 喜欢的风味。
- 是否需要加奶。
- 奶种偏好。
- 杯型或预算。
- 需要避开的原料。

收到合法推荐后：
- 推荐饮品弹出并进入展示状态。
- 柜台对应展示杯高亮。
- 在侧边或上方显示推荐配置的原料。
- 显示价格及当前可售状态。

用户可以继续调整该饮品允许修改的原料和杯型。
调整后，展示内容、价格及可售状态同步更新，
最终下单以用户修改后的配置为准。

用户选择“换一杯”时：
- 重新获取最新快照并请求其他推荐。
- 当前饮品退出展示状态。
- 新推荐饮品进入相同的展示与选择流程。

用户也可以主动选择其他饮品，
进入与直接点单相同的展示流程。

推荐请求期间显示等待状态，避免重复提交。
请求失败时显示说明并允许重试。

推荐面板关闭后，不应因迟到的请求结果自动重新打开，
也不应重新显示已结束交互的饮品。

### 2.6 确认下单

直接点单和推荐点单共用同一套确认流程。

用户点击“确认下单”后：
1. 保存当前选择的副本，作为本次订单内容。
2. 禁用重复下单、饮品切换和原料修改。
3. 调用确认接口，重新校验整笔原料需求。
4. 全部原料足够且保存成功后，才进入制作动画。

确认失败时：
- 显示库存不足、配置无效或保存失败的原因。
- 不播放购买成功动画。
- 保留当前面板并刷新可售状态。
- 恢复允许的操作，供用户修改或重试。

菜单此前显示“可售”，不能替代确认时的库存校验。

### 2.7 制作动画

确认成功后，按已确认配置播放制作动画：
- 展示所选原料向杯中移动、汇合或倒入。
- 黑咖啡展示咖啡萃取液、水和冰进入杯中。
- 拿铁展示咖啡萃取液与所选奶进入杯中。
- 咖啡豆可使用简化的研磨、萃取表现，
  不直接将整颗咖啡豆倒入成品杯。

动画使用已确认订单的配置及配方，
不读取用户后来修改的当前选择。

动画只负责视觉反馈，不再次确认订单或扣库存。

### 2.8 购买完成

制作动画结束后：
1. 显示“购买完成，谢谢惠顾！”
2. 短暂停留后关闭本次点单或推荐弹窗。
3. 清除商品高亮与原料展示。
4. 展示模型恢复初始状态。
5. 镜头恢复接待前的位置。
6. 结束本次接待。

确认成功时，库存已经扣减并保存。
即使动画意外中断，也不能自动重复下单或再次扣减。

### 2.9 返回、关闭与离开

返回按钮：
- 返回欢迎选项。
- 清除当前饮品高亮及原料展示。
- 不产生购买。

关闭面板、选择“稍后再来”或离开接待区域：
- 结束本次接待。
- 关闭交互 UI。
- 清除高亮及原料展示。
- 恢复展示模型和镜头。

同一次进入接待区域期间，只自动招呼一次。
结束接待后，需离开并重新进入区域，才允许再次自动招呼。

制作期间暂时禁用关闭和返回按钮。
若用户离开区域，已确认的订单仍然有效，
不得因离开而重复确认或自动回退库存；
完成后也不应向区域外用户重新弹出交互面板。

## 3. 当前菜单与后续扩展

当前菜单包含：
- 蓝山黑咖啡
- 瑰夏黑咖啡
- 科纳黑咖啡
- 拿铁

后续可能新增饮品，系统不固定为四款。

正式菜单 UI 根据菜单服务返回的数据生成，
不在脚本中固定饮品数量。

每款饮品通过唯一商品 ID 关联：
- 菜单名称与合法选项。
- 配方、价格及库存需求。
- 展示模型与高亮对象。
- 原料展示及制作动画。

当前商品 ID：

| 饮品 | 商品 ID |
|---|---|
| 蓝山黑咖啡 | black-blue-mountain |
| 瑰夏黑咖啡 | black-geisha |
| 科纳黑咖啡 | black-kona |
| 拿铁 | latte |

新增饮品时需补充：
- menu.json 中的菜单定义。
- 适用配方及合法配置。
- 展示模型和商品 ID 对应关系。
- 原料展示与动画配置。

新增原料时还需补充原料目录，

仅修改初始库存种子，不会更新已有实时库存文件。

需要同步扩展计价、校验或动画脚本，不能只添加 JSON。

LLM 的推荐范围以每次获取的最新菜单与库存快照为准。

## 4. 杯型、原料与配方

当前饮品提供 400ml、500ml 两种杯型。

### 4.1 黑咖啡

- 三款黑咖啡分别使用固定豆种。
- 不提供自由更换豆种或奶种的选项。
- 更换豆种需要切换到另一款黑咖啡。
- 展示咖啡豆、水、冰及萃取液制作目标。

### 4.2 拿铁

可选咖啡豆：
- 蓝山。
- 瑰夏。
- 科纳。

可选奶：
- 全脂奶。
- 脱脂奶。
- 燕麦奶。

首次选择拿铁时，默认蓝山豆和全脂奶。
初始杯型为 400ml；后续选择饮品时保留当前杯型，
前提是该饮品支持该杯型。

### 4.3 当前演示配方

| 饮品/杯型 | 豆(g) | 萃取液目标(g) | 水(ml) | 冰(g) | 奶(ml) |
|---|---:|---:|---:|---:|---:|
| 黑咖啡400 | 18 | 30 | 150 | 200 | 0 |
| 黑咖啡500 | 18 | 36 | 220 | 230 | 0 |
| 拿铁400 | 20 | 40 | 0 | 0 | 250 |
| 拿铁500 | 20 | 40 | 0 | 0 | 330 |

以上为项目演示参数：
- 仅咖啡豆和奶参与库存扣减。
- 萃取液为制作目标，不是独立库存。
- 水和冰用于配方展示及动画。

运行时以配方文件和服务返回的数据为准。

### 4.4 当前计价规则

所有金额使用整数分计算。

咖啡豆每 5g：
- 蓝山：300 分。
- 瑰夏：350 分。
- 科纳：400 分。

奶每 100ml：
- 全脂：300 分。
- 脱脂：350 分。
- 燕麦：400 分。

按实际用量比例计价：
- 黑咖啡加水冰费 300 分。
- 500ml 统一加 200 分。
- 拿铁不收水冰费。
- 不收取萃取液费用。

UI 显示金额时转换为元，不使用浮点数重新计价。

全脂奶和脱脂奶含牛奶。
燕麦奶不保证没有过敏风险。
咖啡风味描述仅代表倾向，不作为确定承诺。

## 5. 库存与售罄显示

打开菜单及库存变化时，刷新可售状态。

不可售的具体配置：
- 显示灰色及 Sold out。
- 显示缺货原因。
- 禁止确认购买。

原料选项：
- 根据当前饮品、杯型及其他已选选项判断可用状态。
- 不可用的选项禁用，并显示原因。
- 切换配置后重新计算可售状态。

商品整体状态：
- 某一个杯型或豆奶组合缺货，
  不代表整款饮品完全售罄。
- 只有该饮品所有合法配置均不可制作时，
  才将整款饮品标记为 Sold out。

打开菜单、选择饮品、修改原料、查询配方、
请求推荐和播放高亮均不扣库存。

只有用户明确确认购买后，才调用确认接口。

库存确认采用整笔校验：
- 全部原料足够且保存成功，才统一扣减。
- 任一配置无效、库存不足或保存失败，整笔不扣。
- 成功后的库存变化通知用于刷新菜单。

## 6. UI 与展示约定

- 欢迎阶段只显示简短招呼和三个选项。
- 选择点单或推荐后才展开对应面板。
- UI 保持奶油风，使用清晰的深色文字。
- 面板布局保留咖啡厅和饮品展示的可见空间。
- 原料区放在当前饮品侧边或上方，避免遮住杯体。
- 同一时间只显示一个主要交互面板。
- 直接点单和推荐点单共用饮品展示及原料选择组件。
- 菜单数量增加时使用滚动列表等布局，
  不通过无限扩大弹窗容纳新品。

## 7. 现有脚本与接口

### 7.1 接待控制

CafeReceptionController：
- BeginReception()：显示欢迎选项。
- OpenOrder()：打开点单面板。
- OpenRecommendation()：打开推荐面板。
- EndReception()：结束接待并关闭面板。

当前 Start() 自动开始接待。
后续接近触发接入后，需要替换该自动开始行为。

OrderOpened、RecommendationOpened、
ReceptionEnded 用于通知其他模块。

不要将这些事件绑定回同名接待方法，
避免事件递归调用。

CafeMenuController 保持启用，
不放在会被关闭的面板下面。

### 7.2 当前选择

使用 CafeMenuSceneAdapter：
- SelectDrink(string)：选择饮品。
- SelectBean(string)：选择豆种。
- SelectMilk(string)：选择奶种。
- SelectCupSize(int)：选择杯型。
- SetQuantity(int)：设置数量。
- RefreshDisplay()：刷新价格与可售状态。
- ConfirmCurrentSelection()：确认购买，会尝试扣库存。

CurrentSelection 返回当前选择的副本。

应用拿铁推荐配置时：
1. 先调用 SelectDrink。
2. 再设置豆种、奶种、杯型和数量。
3. 读取最终状态并更新展示。

原因是 SelectDrink("latte") 会初始化默认豆奶选项。

Adapter 事件：
- PriceChanged(string)：当前选择总价。
- StatusChanged(string)：可制作状态或失败原因。
- CanConfirmChanged(bool)：是否允许确认。
- ResultChanged(string)：最近一次确认结果。
- ConfirmationCompleted(bool, string)：确认成功与否及说明。

制作动画只在确认成功后启动。
确认成功后应保持购买按钮禁用，直到本次流程结束，
避免动画期间再次下单。

### 7.3 菜单与库存查询

统一通过 CafeRuntimeServices.Menu 获取共享服务，
在 Unity 主线程使用，不在每次刷新时重复创建。

GetMenuOffers()：
- 返回所有合法单杯组合的报价及可售状态。
- UI 按商品 ID 分组，生成整张菜单。
- 当前返回 24 种组合；扩展后数量可能变化。
- 返回结果不预占库存。

TryGetRecipe(selection, out recipe, out reason)：
- 返回合法选择对应的单杯配方副本。
- 用于原料展示与制作动画。
- 查询不扣库存。
- 合法配方即使缺货也可以查询。

GetRecommendationSnapshotJson()：
- 返回菜单、配方、风味、价格及实时库存快照。
- 每次推荐请求前重新获取。
- 不作为最终购买可售保证。

InventoryChanged：
- 触发后刷新菜单及当前选择状态。
- UI 禁用或销毁时取消自行添加的订阅。

### 7.4 商品高亮

CafeProductHighlighter：
- HighlightProduct(string productId)：高亮指定饮品。
- ClearHighlight()：恢复原材质。

当前使用发光材质替换指定 Renderer 的材质槽。
新增商品时补充商品 ID、Renderer 和材质槽配置。

高亮脚本只负责材质切换。
饮品上移、放大、退出展示等动画由展示模块负责。

### 7.5 整笔订单

如后续加入多杯或购物车，由订单程序调用：

CafeRuntimeServices.Menu.TryConfirmOrder(...)

该接口汇总整笔订单的原料需求并统一确认。

同一次购买只能由一个入口执行确认，
不能同时调用 Adapter 确认和订单服务确认，
以免重复扣减。

## 9. 模块协作约定

接待模块：
- 管理欢迎、点单、推荐及结束状态。
- 后续接入接待区域检测和镜头切换。

菜单与库存模块：
- 提供合法选项、配方、报价与可售状态。
- 负责确认时的库存校验、扣减和保存。

饮品展示模块：
- 负责当前饮品弹出、切换与恢复。
- 根据商品 ID 调用高亮。
- 保证同一时间只有一个当前展示饮品。

原料展示模块：
- 根据当前选择查询配方。
- 更新原料名称、图标或模型与用量。

LLM 模块：
- 获取最新菜单与库存快照。
- 返回回复文字和可识别的推荐配置。
- 推荐配置由程序校验后应用。
- 不直接调用购买确认接口。

制作动画模块：
- 使用已确认配置及配方播放。
- 动画结束后通知接待模块完成流程。
- 不再次扣减库存。

直接点单和推荐点单共用展示、配置、计价、
库存校验和制作动画，避免维护两套独立流程。

## 10. 分支与场景协作

- main 保存阶段性验证通过的版本。
- dev 用于当前团队共同开发与集成。
- 开始工作前 Fetch，并在有更新时 Pull。
- 切换分支或拉取场景更新前，保存工作并关闭 Unity。
- 提交资源时保留对应 .meta。
- 不提交 Library、Temp、Logs 等缓存目录。
- 不提交 API Key 或其他凭据。
- 提交说明写清本次完成的功能及验证情况。

CafeMain 场景暂由场景负责人统一修改。
其他成员优先通过脚本或独立 Prefab 提供功能，
需要修改共享场景前先协调。

共享 dev 仍可能产生冲突；
尽量避免同时修改同一场景、Prefab 或脚本。

## 11. 基本验收

语音识别默认使用阿里云百炼 Qwen-ASR（北京地域）。
在 Unity 菜单 `Virtual Cafe → Speech Settings` 填入百炼 API Key，
点击 `Save on this computer`，再进入柜台的 `Voice conversation / 语音点单`。
选择中、英或日语，点击麦克风录音，再次点击停止并识别（最长30秒），
识别结果进入原有点单流程；店员只用文字回复。

配置保存在 `UserSettings/CafeSpeech.local.json`，不进入版本控制；
打包后使用 `Application.persistentDataPath` 下的同名文件，字段为 `aliyunApiKey`。
也可设置环境变量 `DASHSCOPE_API_KEY` 后重启 Unity；本地文件中的非空密钥优先。
录音发送到阿里云进行识别，不写入磁盘。对话模型继续使用 `LLM Settings`。
获取密钥：https://help.aliyun.com/zh/model-studio/get-api-key 。
通过 `Virtual Cafe → Speech → Run Audio Checks` 可运行音频及百炼协议检查。

接待：
- 欢迎选项能够进入点单、推荐和结束流程。
- 同一次进入接待区域不会反复自动招呼。

展示：
- 选择饮品时显示正确模型及原料。
- 切换饮品时，旧展示退出，新展示进入。
- 返回或结束时清除高亮并恢复模型。

配置：
- 豆种、奶种或杯型变化后，
  原料展示、价格及可售状态一致。
- 黑咖啡不出现不允许的豆奶选择。

库存：
- 缺货配置显示 Sold out，并禁止下单。
- 确认失败不扣库存、不播放成功动画。
- 确认成功只扣减一次，并刷新库存状态。

推荐：
- 使用最新快照，并校验返回的商品与选项。
- 推荐与用户修改后的配置正确显示。
- 关闭面板后，迟到的回复不会重新打开交互。

购买：
- 先确认成功，再播放对应配方的制作动画。
- 动画期间无法重复下单。
- 完成后显示感谢语并关闭对应弹窗。

扩展：
- 新增饮品后可通过配置进入菜单和推荐流程。
- 不依赖固定四个按钮或固定数量的商品。
